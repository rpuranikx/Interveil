Stop an AI agent's harmful tool calls before they run.

Interveil is a self-hosted gateway between your agents and their tools. You write rules in YAML. Every tool call a model proposes is checked against them, and the ones you haven't allowed never reach your agent.

What changes when Interveil is in the path

Your agent fires calls at four systems. The harmful ones look like any other call until they land. With Interveil switched on, they stop at the veil and only safe calls get through.

An illustration. The rule names are real: large-refunds comes from the demo policy and the rest from the built-in command blocklist.

How it works

  1. Point your agent at it

    Change the base URL or the MCP server URL. Claude Code gets a hook with one command.

  2. Write the rules

    YAML per agent, with conditions on the arguments. If the file is broken, the server refuses to start.

  3. Calls are checked

    Allowed calls pass through untouched. The rest are withheld, recorded in the trace and sent as alerts.

Connect your agent

Opens the dashboard and runs the support-agent scenario with a scripted model, so it needs no API keys.

cd Interveil && pnpm install && pnpm demo

Works with any OpenAI-compatible client, in any language, for OpenAI, Anthropic and Gemini models. Your provider key is forwarded and never stored.

client = OpenAI(
    base_url="http://localhost:3000/v1/proxy",
    default_headers={"x-interveil-agent-id": "support-agent"},
)

Writes a fail-closed PreToolUse hook, pins the policy so the hook only trusts a server that signs its answers, and turns on Claude Code's sandbox so the agent can't read the key. If the server is down, tool calls are denied. On Windows, run Claude Code inside WSL2.

cd ~/your-project && node ~/Interveil/interveil/dist/cli.js init claude-code
node ~/Interveil/interveil/dist/cli.js serve --preset coding-agent

Point your MCP client at the proxy, which speaks Streamable HTTP. A blocked tools/call never reaches the server.

# MCP server URL
http://localhost:3000/v1/mcp

Wrap an agent object in TypeScript or Python. A disallowed method call throws PolicyViolationError before it runs.

import { trace } from 'interveil';
const agent = trace(new MyAgent(), { agentId: 'billing-agent', policyFile: './policy.yaml' });

Rules you can read

Policies live in version control next to your agent. This is the file the demo runs.

support-agent.yaml

agents:
  - id: support-agent
    rules:
      - id: large-refunds
        action: block
        message: Refunds over $100 need a human
        condition:
          tool: issue_refund
          args.0.amount: { greaterThan: 100 }
      - id: audit-refunds
        action: allow_and_audit
        condition: { tool: issue_refund }
  1. Per agent. The id matches the x-interveil-agent-id header your client sends.
  2. Inside the arguments. A $49 refund passes and is recorded for audit. A $4,900 one is withheld.
  3. Fails closed. A typo, an unknown action or invalid YAML stops the server from starting.

What it doesn't do

  • It only governs traffic that goes through it. It is not a sandbox.
  • It decides on what the model proposed. It can't see what an agent does with a call it allowed.
  • Agent identity is asserted by the client, through a header.
  • Command blocking is pattern matching: a speed bump for obvious damage, not a guarantee. For coding agents it leans on Claude Code's sandbox, which doesn't run on native Windows.
  • One process and one SQLite file, with no multi-user accounts yet.
