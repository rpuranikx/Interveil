Your agents act. Your policy checks first.

    
The veil between your AI agents and your infrastructure.

    
Interveil is a gateway for AI agents. Point an agent's model or MCP traffic at it, and every tool call the model proposes is checked against your YAML policy before the agent can execute it. You get a live trace of every step and an alert when something is blocked.

01 / The problem
Agents act on what they read.

      
An agent with tools can move money, run commands and change files, and it decides what to do from text it can't fully trust.

    

    

      
THREAT · 01
Prompt injection
Instructions hidden in a web page, a ticket or a tool result can steer the model into calls nobody asked for.

      
THREAT · 02
Irreversible actions
A deleted directory, a refund or a piped shell script can't be undone by noticing it in a log afterwards.

      
THREAT · 03
No visibility
Without a trace, there's no record of which model call led to which tool call, or why.

      
THREAT · 04
Compliance gap
Regulated teams need an audit trail of automated decisions, and most agent stacks don't produce one.

SYS·01


agent ──► [ interveil ] ──► model
             │  ▲
   tool call │  │ allowed
             ▼  │
          [ policy ] ✕ blocked

            
Gateway & MCP enforcement

            
An OpenAI-compatible endpoint for OpenAI, Anthropic and Gemini models, plus native Anthropic Messages and OpenAI Responses routes for Claude Code and Codex, streaming or not. Proposed tool calls are checked before the agent receives them; disallowed ones are withheld and replaced with the reason.

            
    
              
  • MCP proxy speaks Streamable HTTP and is tested with the official MCP SDK
    • 
              
  • Each tools/call is checked first; a blocked call never reaches the MCP server
    • 
            

            

          

          

            
SYS·02


- id: large-refunds
  action: block
  condition:
    args.0.amount:
      { greaterThan: 100 }

            
Policy as code, fail-closed

            
YAML rules per agent or for all agents, with conditions on any argument (greaterThan, matches, oneOf…), audit, block, approval and halt actions, and session rules that follow a flow across calls, such as a network call after a secret was read. An invalid policy stops startup; halts survive restarts.

            
    
              
  • Destructive-command blocklist catches rm -rf ~, curl | sh, DROP TABLE and private-key reads in commands and paths, while code an agent writes is left alone
    • 
              
  • Quoting and spacing variants are caught too, while ordinary text such as "format the answer" is left alone. One shared test corpus covers TypeScript and Python.
    • 
            

            

          

          

            
SYS·03


07 POLICY VIOLATION   large-refunds
08 POLICY VIOLATION   pipe-to-shell
   └─► webhook  POST  200 OK
       x-interveil-signature: sha256=…

            
Live trace & alerts

            
Every request, response and policy decision streams to a dashboard over WebSocket and persists in SQLite, with prompts, tokens and latency per step.

            
    
              
  • Each violation posts a signed (HMAC-SHA256) alert to Slack, PagerDuty or any endpoint
    • 
              
  • Alerts are sent in the background, without slowing the agent down
    •

03 / How it works
Three steps. One line of code.

      
You don't rewrite your agent. You change where it sends model traffic, describe what it may not do, and Interveil stops those calls before your agent ever sees them.

    


    

      

        
STEP 01

        
Point your agent at Interveil

        
Swap the base URL. Your provider key is forwarded, never stored. The agent id tells Interveil which rules apply.


# your agent's client, now behind Interveil
client = OpenAI(
  base_url="http://localhost:3000/v1/proxy",
  default_headers={
    "x-interveil-agent-id": "billing-agent"
  },
)

      

      

        
STEP 02

        
Write the rule

        
Policies are plain YAML in version control. A bad policy fails to load instead of silently allowing everything.


# policy.yaml
agents:
  - id: billing-agent
    rules:
      - id: large-refunds
        action: block
        message: Refunds over $100 need a human
        condition:
          tool: issue_refund
          args.0.amount: { greaterThan: 100 }

      

      

        
STEP 03

        
Disallowed calls never land

        
When the model proposes a forbidden tool call, Interveil withholds it and tells the agent why. Everything else passes through untouched.


# what the agent receives
finish_reason: "stop"
content: "[Interveil] Tool call blocked
  by policy: issue_refund
  (rule \"large-refunds\": Refunds
  over $100 need a human)."
✕ issue_refund($4,900) withheld

04 / Deploy
Running in three commands.

      
One self-hosted Node.js process with a SQLite file. Run it next to your agent on a laptop, or as a container in front of a fleet.

    

    

      

        
LOCAL · NODE 22.12+

        
From source

        
Not yet on npm or PyPI; install from the repository.


# try it with no API keys
git clone https://github.com/rpuranikx/Interveil
cd Interveil && pnpm install
pnpm demo

# run it for your own agents
pnpm build
node interveil/dist/cli.js serve \
  --policy-file policy.yaml

      

      

        
CONTAINER

        
Docker

        
Published on 127.0.0.1:3000 only. Traces persist in a named volume; settings come from interveil/.env.


docker compose up

# dashboard + API
http://localhost:3000

# every setting, documented
interveil/.env.example

      

      

        
BEFORE YOU EXPOSE IT

        
Production checklist

        
Interveil is local by default. To serve it to a team or a fleet:

        
    
          
  • Set INTERVEIL_API_KEY; it's then required on the API, gateway and WebSocket
    • 
          
  • Bind beyond localhost with --host 0.0.0.0
    • 
          
  • Load your rules with --policy-file; invalid files stop startup
    • 
          
  • Add alerts.webhooks to the policy for signed violation alerts
    • 
          
  • Behind a proxy, set INTERVEIL_TRUST_PROXY for per-client rate limits
    •

05 / Evidence
Built to enforce, and measured.

      
Every number here comes from the repository: pnpm bench, the test suites, and pnpm audit.

    

    

      
0.31ms
added latency, p50
Gateway overhead with the in-memory store; about 0.55 ms with SQLite persistence.

      
366
automated tests
357 TypeScript and 9 Python, run in CI with a Docker build and a demo smoke test.

      
48/ 0
blocked / false alarms
The shared blocklist corpus: 48 destructive inputs blocked, 22 ordinary ones allowed.

      
0
known vulnerabilities
In production dependencies, per pnpm audit --prod.

    

    

      
Pre-execution
Disallowed calls are stopped before they run, not flagged afterwards.

      
Fail closed
A bad policy stops startup; an unreachable policy server, or a hook that fails to run, refuses the call.

      
Local by default
Binds to localhost, refuses cross-site browsers and DNS-rebinding hosts, and needs an API key to be exposed.

      
Honest limits
It governs traffic that goes through it. It is not a sandbox; the README says exactly what it doesn't cover.

    

    
Latency measured on an i7-8550U laptop against a local fake provider, so it is the gateway's own overhead, not end-to-end time.

  







  

    

      
06 / Architecture
One process, four ways in.

      
A single self-hosted Node.js server. Every entry point shares one policy engine, one trace store and one live dashboard.

07 / Roadmap
Where it's going.

      
What's shipped, and what's next.

    

    

      
✓ Shipped
Tracing and live dashboard
Execution traces from SDKs, the gateway and the MCP proxy, streamed live and stored in SQLite.

      
✓ Shipped
Enforcement everywhere traffic flows
Tool-call enforcement at the gateway for OpenAI, Anthropic and Gemini, plus native Messages and Responses routes, streaming included; MCP proxy; policy API and a fail-closed Claude Code hook.

      
✓ Shipped
Coding-agent guardrails
A coding-agent preset, session rules for read-a-secret-then-send flows, self-protection against an agent turning Interveil off, and Claude Code's own prompt for require_approval.

      
✓ Shipped
Policy as code and integrations
Fail-closed YAML policies, persistent halts, signed webhook alerts; examples verified against the OpenAI Agents SDK, the MCP SDK and Claude Agent SDK hooks.

      
◐ Next

Published npm and PyPI packages, and an approval queue for require_approval at the gateway and MCP proxy.
